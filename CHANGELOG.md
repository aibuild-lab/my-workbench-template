## 2026-11-07, a Workforce save refuses when the privacy check is missing

- `aibl-checkpoint` step 2.5 now first looks whether this is an Agent Workforce workbench: either of the course's own enrollment stamps, `.aibl/programs/agent-workforce.json` or `.aibl/workforce-student-edition.json` (the same two files the course's `start_fresh.py` reads; every published edition since the first, 09-21, ships the first one), or the check file itself. It only looks at whether the files exist. A stamp without `workforce/runtime/privacy_check.py` refuses the save: nothing is staged, deleted or moved, and the student hears what is missing and the fix, the update paste on Agent Workforce card 0.3, Get your organization, in Learn, with a second line: if they see this again after the update, post in the course channel. The update does bring the file back on a workbench enrolled before 10-06, because the course adds it. It does not on a workbench whose own history deleted it: tested with the published `student` branch on Windows, the update's merge left the file deleted when the newer course commit did not change it, and gave a keep-mine or take-the-program's conflict when it did. The agent gives no Git commands for this. That matches the course's own checkpoint skill, where a missing check never counts as a pass. Workbenches with neither stamp nor check file (Camp, Essentials, Team HQ, no program) skip the step and save exactly as before; a Team HQ stamp alone is not Workforce. `~/.aibl/workbench.json` is not used: it is written only on a yes in enroll's last step, so many enrolled workbenches have none, and it lives outside the workbench. Why: before this, a Workforce workbench without the check (enrolled on an edition before 10-06, or with the file removed) fell back to step 2's list alone (D210, Wade's ruling 11-07). Tests: `tests/checkpoint_privacy_check.py` (routing tests need no course script). Undo: revert this PR's merge commit.

## 2026-11-07, saving runs the course privacy check

- `aibl-checkpoint` new step 2.5 and step 4: when the workbench has the course's check (`workforce/runtime/privacy_check.py`, so Agent Workforce), a save runs its `gate` before anything is staged and its `staged` look after staging, before the commit. Only exit 0 (for the gate, with its `Clear:` line) lets the save go on. Exit 3 stops the save and the student hears in plain words what it found and what they can do: the check's own `untrack --yes` or `ignore --yes` on their yes, or, for a `.gitignore` line that could undo the protection, the file and line number with how to remove it themselves (the agent never edits that line or offers to, even when asked). A private file staged past the ignore rules (a folder link, a short Windows name) is taken out of the snapshot with `staged --unstage` and the save stops. A check that could not run stops the save too. Nothing deletes, moves or edits the student's files. Workbenches without the file (Camp, Essentials, Team HQ) skip the step and save exactly as before; step 2's list check is unchanged. Why: the save left private items out by its own list only, which misses a removed ignore line, a `!` line that undoes one, and files reached through a folder link (D207, Wade's yes 11-07). Tests: `tests/checkpoint_privacy_check.py` (text checks always; real-Git checks with `AIBL_PRIVACY_CHECK` set to the course script). Undo: revert this PR's merge commit.
