## In Codex: one permission for each protected write

In Codex, an agent can't change this workbench's history (`.git`), its `.agents` or `.codex` folders, or anything outside the workbench, and can't use the network, unless the student allows that step. Claude Code has no such step: there, run the steps as written. In Codex, every write in the table below follows these five rules, and each step that makes one says so with "(Codex: one permission per write.)":

- **One plain line first.** Before the command, say in one plain line what is about to change, then the course's Week 1 words for the box: "If Codex asks you to allow a save to your workbench's history, that's this save; choose to allow it." for a save to the workbench's history, "If Codex asks you to allow a change to your agent files, that's this step; choose to allow it." for a change to the agent files, and "If Codex asks you to allow it, that's this step; choose to allow it." for any other write. Use the step's line from the table, with the program's name. Never show the command, a file path or a word in capitals in that line.
- **Its own command, with the permission asked together with it.** Run each write as one command on its own, never joined to another with `&&`, `;` or `|`, and never inside a script you write to run several. Request the app's permission together with that exact command when you run it: ask to run it outside the sandbox, with a one-line reason that names the same step as your plain line, so the box the student sees names the step you just named. Never try it first and ask only after it fails: Codex does not offer the permission on its own. If a write you ran without asking fails with a read-only or permission message (such as "Unable to create .git/index.lock: Permission denied"), that is not the student's no: run the same command once more, alone, with the permission asked.
- **One line and one box per write.** A commit of files Git already tracks is one command, `git commit -m "<message>" -- <paths>`; a new file needs `git add -- <path>` first, its own command. Read-only commands (`git status`, `git diff`, `git log`, `git ls-tree`, `git rev-parse`, `git remote get-url`, `git merge-base`, and the reports that say they write nothing) need no line and no permission. Step 1's `--joining-from` report is run without asking: its one optional write is the Camp record, and when Codex refuses it the report says `camp.recorded: false`, which step 1 already handles.
- **Never a terminal step for the student.** You run every command. Never hand the student a command, a box with a command in it, or a step in a terminal or PowerShell, even when a permission is refused.
- **If it isn't allowed, wait.** If the student doesn't allow it, or no box comes (for example the session's approval policy is never, so no permission can be asked), stop at that step. When you stop there, that reply is exactly two lines: the step's plain line, then its waiting line, word for word from the table, even when you knew before running it that no box could come. Nothing before them and nothing after: no note that a permission is needed or can't be asked, no quote of this skill, no file link, no word about the app's settings or policies. Then do nothing else: no other command, no other way to make the same change, no choices of your own, and never say or suggest the step happened. On "try again", recheck that the workbench and the pinned commit are as they were, say the plain line again, and run the same command with the permission asked. Two writes carry on instead of waiting, as the table says: the Camp record and the course's run note.
